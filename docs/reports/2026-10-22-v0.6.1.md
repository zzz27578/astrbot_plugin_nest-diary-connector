# 小窝 0.6.1 更新报告

日期：2026-10-22（Asia/Shanghai）

本次修复同一天第二次写日记覆盖早先事件的问题，并为备忘录图钉板加入自适应分页。升级不改变旧数据格式，不要求重新建日记本或备忘录。

## 日记续写

原先 `DiaryService.write_diary()` 将新正文直接保存为该日期的整篇日记。即使留下了修订快照，正在查看的正文也只剩下最近一次写入的内容。

现在 bot 工具、内嵌客户端和 Bot API 默认使用 `append`。例如上午写入“上午一起散步”，下午写入“下午一起做饭”，最终正文同时保留这两段。第三次继续追加，日记本和日期仍是独立边界。

续写保留原标题，合并情绪、标签、人物和媒体引用，避免早先事件失去检索入口。每次修改增加修订号并在写入前保存旧文快照；快照文件名带微秒，连续写入不会覆盖先前快照。同进程的独立服务实例共用写锁，避免同时续写时互相丢失内容。

`mode=replace` 保留完整重写能力，供用户明确提出重写或整篇更正时使用。网页编辑器继续保存完整正文，避免编辑一次又把整篇重复追加。旧请求无需增加参数；不填写 `mode` 的 bot 写入自动获得续写保护。

工具说明、隐藏规范、托管未来任务和 `skills/nest-diary/SKILL.md` 都要求先读取旧日记，只提交新事件。完全相同的整篇正文、相同的最后一次补写，以及携带旧正文再续写的请求，都有基本重复保护；对于换了措辞的重复事件，依靠 bot 读取旧文判断，服务端不会猜测并删除记忆。

原修订快照保持不变。此前已被覆盖的事实不会凭空重新生成；若旧快照中保留了原文，仍可依据快照恢复。

## 备忘录分页

板面根据当前可见宽度、高度、纸条尺寸和主题实际布局计算行列数量。纸条超过容量即进入后续页，板面不会随总条数持续加长。

底部显示“上一页 / 第 X / Y 页 / 下一页”和当前筛选下的纸条总数。首尾页禁用对应按钮，按钮有键盘焦点和状态说明，颜色沿用主题变量。桌面 1440 × 900 的测试场景每页 8 张；375px 手机每页 1 张。改变窗口大小后重新计算容量，并尽量保留当前页第一张纸条附近的位置。

编辑保存后定位回相应纸条所在页；删除、归档或筛选减少页数时自动收回有效页。置顶、归档、敏感隐藏、全文编辑与删除继续使用既有 API，分页本身不改写备忘录文件。旧的 `nestMemoBoardPlacements` 本地存储继续保留，显示时约束超出板面的偏移，避免旧位置导致纸条不可见。

手机端仅在备忘录页面使用紧凑横向导航，当前入口自动保持可见。低高度横屏仍允许外层页面正常滚动，纸条板保持有限行数并通过分页控制数量；没有把全文缩小到难以阅读的尺寸。

WebUI 的资源同步到 AstrBot 插件页，前后端版本号与 HTML 缓存参数均更新为 0.6.1。

## 数据兼容

- 插件内部名称、已有配置文件名和数据目录未更名。
- 日记 Markdown 的字段、备忘录 JSON、日记本和备份结构保持兼容。
- 读取旧版默认目录中的日记后再续写，原文件保留；列表优先显示当前记录，不重复列出同日期日记。
- 非补零日期继续按原样定位，未做日期名归一化。
- 未改动备忘录后端存储、权限和读写协议；翻页不写入旧纸条文件。
- 原有自定义写作规范保留，续写要求额外注入，避免升级覆盖个人设置。
